## 核心原则

1. **安全第一 (Dry-Run First)**：在执行大范围的文件重构、合并或删除之前，必须先生成报告并询问用户确认。
2. **脚本优先**：对于纯粹的语法错误（如死链）、格式错误（如缺少 Frontmatter），优先调用确定性的 Python 脚本（`python scripts/lint.py --check`）进行批量修复，避免消耗过多 LLM Token。
3. **语义级体检**：利用 LLM 的阅读能力，重点发现传统代码 linter 无法发现的“语义问题”，如相似概念的分裂、观点的陈旧、或者应该建立但未建立的跨界链接。

## 流程

### 1. 扫描与检查范围

| 检查项                    | 定义                             | 处理策略                                             |
| :------------------------ | :------------------------------- | :--------------------------------------------------- |
| **Orphans (孤儿节点)**    | 没有任何 `[[ ]]` 指向它的页面    | 分析内容，主动为其寻找父节点或将其挂载到 MOC 索引页  |
| **Dead Links (死链)**     | `[[xxx]]` 指向了一个不存在的文件 | 尝试模糊匹配寻找正确文件名，或询问是否创建空节点占位 |
| **Tag Sprawl (标签发散)** | 未收录在 `moc/TAGS.md` 中的标签  | 将其重命名并入标准标签族，或请求将其加入标准字典     |
| **Redundancy (语义冗余)** | 多个页面描述相同或高度重合的内容 | 生成差异对比，建议合并                               |

### 2. 操作日志格式

```markdown
## [YYYY-MM-DD] lint | 常规巡检/深度重构

- **脚本修复 (Automated)**:
  - 修复死链: N 个
  - 补全 Frontmatter: N 个文件
- **AI 结构优化 (Semantic)**:
  - 合并页面: 将 `[[A]]` 和 `[[B]]` 合并至 `[[C]]`
  - 消除孤岛: 为 `[[Orphan_X]]` 找到了 3 个关联节点
  - 规范标签: 批量将 `#llms` 替换为TAGS.md中的 `#LLM`
```
